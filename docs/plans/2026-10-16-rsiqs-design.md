# RSIQS 设计文档：A 股盘前推荐 + 自我迭代系统

日期：2026-10-16

## 目标与边界

- 目标：每个交易日开盘前给出 A 股推荐（≤5 只），模拟交易并持续自我迭代，以扣成本后相对沪深 300 的超额收益为衡量标准。
- 不做实盘下单。Claude 只出信号，用户手动执行。
- 运行环境：本机 Windows，Python 3.12，Windows 任务计划调度。
- Claude 接入：以子进程调用 Claude Code 无头模式（`claude.exe -p --bare`），默认 `claude-opus-5-5`。鉴权走 `.env`：中转地址 + Token，或官方 API Key。用户的中转只放行 Claude Code 客户端，直接用 SDK 调用会被拒（2026-10-19 实测）。
- 推送：企业微信群机器人 webhook（地址存 `.env`）。
- 资金规模参考：50 万元以上，用于设定仓位和冲击成本假设。

## 三条基本前提

1. 系统不保证盈利，核心是诚实衡量是否有效。
2. LLM 层不可历史回测（模型训练数据截止 2026 年中，存在前视偏差），只能前向模拟验证；量化层可回测。
3. 防自欺：评估器、账本、留出集锁定，agent 只能改策略和 playbook。

## 架构：混合（量化层 + LLM 层）

- 量化层：因子打分出候选池，可回测，由 Claude 研究循环迭代。
- LLM 层：盘前读新闻、公告、竞价数据，对候选做否决或调权，只做前向验证。
- 影子账户并行模拟：纯量化 / 量化+LLM / 沪深 300 基准 / 各候选策略。用数据回答"LLM 层是否增值"。

## 每日时间线

| 时间 | 任务 | 内容 |
|---|---|---|
| 15:30 | 收盘结算 | 拉日线，按 A 股规则结算模拟单，更新各账户净值 |
| 16:00 | 复盘 | Claude 对比昨日推荐与实际走势，写复盘，更新 playbook，推送日报 |
| 22:00 | 研究 | 每周或有预算时，agent 提出策略变体并回测，合格者进影子盘 |
| 08:30 | 盘前扫描 + 深度分析 | 隔夜新闻、公告；量化候选池；Claude 深度分析（不限时），给每只候选写好竞价条件（可接受的高开/低开区间、最高买入价、止损、目标） |
| 09:25 | 竞价定稿 | 拉竞价数据，先按盘前条件做规则过滤，再做一次轻量 Claude 确认（只能否决、不能新增），9:28 前推送 |
| 09:30-15:00 | 盘中监控 | 每 1-3 分钟查持仓，触发止损、止盈、炸板等条件时推送 |

### 撮合规则

- 开盘价成交加滑点；买入 100 股整数倍；T+1 由账本保证：只有买入日之前的持仓当天可卖。每个账户每个交易日只撮合一次：账户记录最后撮合日，同一天重复调用不做任何改动，日期倒退直接报错。不建模加仓。
- 板块：60/00 开头为主板，30 开头为创业板（300/301/302），688/689 为科创板，北交所 4/8/92 开头。
- 涨跌幅和费用按成交日当时的规则生效（未给日期时按当前规则）：
  - 涨跌幅：北交所 30%，科创板 20%；创业板 2020-08-24 起 20%，此前 10%（ST 5%）；主板 10%，主板 ST 2026-07-06 前 5%、之后 10%。
  - 费用：佣金万 2.5（最低 5 元）；过户费 2022-04-29 前 0.002%、之后 0.001%；印花税仅卖出，2023-08-28 前 0.1%、之后 0.05%。
- 每日撮合分三步：
  1. 开盘卖出：全天封死跌停不能卖。否则依次为到期按开盘价卖出、开盘价 ≤ 止损价按开盘价止损、开盘价 ≥ 目标价按开盘价止盈；只在盘中触及止损或目标的推迟到第 3 步。
  2. 开盘买入：开盘涨停、开盘价高于最高买入价、开盘价不高于止损价、已持仓或买不足一手时不买（盘前竞价过滤对买入价上限和止损价用同样的口径）；股数考虑最低 5 元佣金，现金不为负。
  3. 盘中卖出：盘中低点触及止损按止损价卖出（止损和目标同日触及时按止损处理），否则按目标价卖出。
- 资金时序：第 1 步回笼的资金当天可用于买入，第 3 步的资金当天不能用。
- 成交价：卖出 ×(1-滑点)、买入 ×(1+滑点)；区间可靠时（见下一条）再截断在当日 [跌停价, 涨停价] 之内。滑点可能让成交价略微超出当日 [最低价, 最高价]，这是有意采用的保守成本假设。
- 涨跌停区间不可靠：开盘、最高、最低价中任何一个超出 [跌停价-0.01, 涨停价+0.01]，说明按昨收算出的区间本身有误（例如除权日的昨收仍是除权前价格，用今天的名称判断历史 ST 状态，或前复权扣减了之后的现金分红）。这时成交价不截断，按开盘价、止损价或目标价加滑点成交；封板只看一字形态：最高价等于最低价才算封死跌停，开盘价等于最高价才算开盘涨停。算错的区间可能窄得多（前复权扣减了之后的现金分红时，高分红股早期原始价格涨跌三四个点就会越过算出的涨跌停价），普通交易日照常成交；一字板仍然买不进、卖不出。根因（缓存拼接处的昨收错位、持仓不随除权调整）尚未处理，计划在执行 Part 3 之前修订计划加入除权除息处理；在此之前这是已知局限，例如除权日的持仓仍按除权前的止损价判断（可能记下假止损），小额除息造成的区间偏移也识别不出来。更彻底的做法是涨跌停判断改用不复权价格（或等比复权），一并在除权除息修订中考虑。
- 停牌与异常数据：成交量 ≤ 0，或开盘、最高、最低、昨收中任一为 NaN 或非正数，都按停牌处理，当天不交易；账本拒绝 NaN 或非正数的成交价。
- 前复权容忍度：日线为前复权价格，舍入后封板价可能与按复权昨收算出的涨跌停价差一分钱，因此涨跌停判断容忍 0.01 元。代价是原始价格离涨停（跌停）一分钱也会被当成封板，结果略偏保守。

### 时效保障

- 盘前分两段。深度分析在 08:30 后做，不赶时间。9:25 的确认调用限时约 110 秒，超时就只按盘前写好的条件过滤；连盘前分析也没有时，退回纯量化推荐，并标注"未经 LLM 审核"。无论哪种情况，都保证 9:28 前推送。
- 关机漏跑：开机后按交易日历补跑结算和复盘；过时的盘前推荐跳过。

## 自我提升循环

### 权限分区

| 区域 | 内容 | Agent 权限 |
|---|---|---|
| `strategies/` | 因子代码、选股参数 | 可改 |
| `playbook/` | LLM 层经验手册、提示词 | 可改 |
| `engine/` | 撮合、账本、评估器、留出集 | 只读，哈希校验 |

每次修改自动 git 提交并附理由，可审计、可回滚。

### 快循环（每日盘后）

- playbook 规则必须引用具体证据（日期、股票、结果）。
- 总长度有上限，超出须合并或淘汰。
- LLM 层每 2 周最多上线一个新版本。

### 慢循环（每周研究）

研究 agent 不给任何工具（`--tools ""`）。Python 把接口、现有策略、历史试验结果都放进提示词。Claude 每轮只返回结构化结果（分析 + 策略代码草稿）。命名检查、import 白名单、编译、评估、写文件全部由 Python 执行，评估结果反馈给下一轮，最多 3 轮。原因：实测 Claude Code 的文件权限规则在 Windows 上表现不稳定，不能当作安全边界。

1. Agent 提出 3-5 个策略变体。
2. 滚动前向回测。数据切分：训练 2016-2024；验证 2025-01 至 2026-06；留出 2026-07 以后（agent 只拿到通过/不通过）。
3. 评分：扣成本后相对沪深 300 超额收益、夏普、最大回撤；强制每日 ≤5 笔。
4. 记录全部尝试次数，用 Deflated Sharpe 校正多重检验。跑不完的评估同样计数；试验在回放留出期之前入库。

评估的完整性：

- 留出期只回传通过/不通过。留出期回放中的任何异常都只记为未通过，不回传异常文本（异常消息可以携带留出期数值）。
- 每段回测只把截断到本段末尾的数据交给策略，训练、验证段看不到之后的数据。
- 策略代码与评估器在同一子进程运行，子进程的 stdout 可能被策略伪造。是否进入影子盘以子进程写入数据库的试验记录为准，stdout 只用于展示训练、验证指标。
- 策略源码检查（尽力而为，不是安全边界）禁止：含双下划线的名字、属性和标识符式字符串（挡住 `_DataView__panel` 这类改编后的私有名字）；按字符串取属性或求值的写法；`print`、`exit`、`SystemExit`。真正的防线仍是 engine/ 哈希校验、git 审计，以及门槛结果只授予影子盘资格。
- 已知局限：留出期（2026-07 至今）随时间滚动延长，与影子盘、现任盘的前向模拟落在同一时间窗。研究上下文里列出的现任、退役状态和现任策略源码，是这段时间前向表现的结果，相当于每次晋升或退役间接透露约 1 比特的留出期信息。它的颗粒度不超过逐次试验已经回传的 holdout 通过/不通过，暂时接受；如果以后研究次数多到值得担心，可以把留出期固定为有限区间，之后的数据只用于前向模拟。

### 晋升

候选 → 回测过门槛 → 影子盘 ≥20 个收益日 → 显著优于现任（年化超额 ≥5% 且 t ≥1.5）→ 成为现任（只推送现任的推荐）。现任在最近 40 个收益日显著落后某个影子（年化 ≤-5% 且 t ≤-1.5）则自动降级并推送通知；降级同样要求显著，否则零超额的噪声也会让现任和影子来回换位。比较前先按日期对齐两条净值，某天缺净值（例如策略选股失败当天跳过）不会被算成超额。

### 预算

`.env` 设每月 API 上限（如 300 元），用完暂停研究循环，盘前推荐不受影响。

## 目录结构

```
rsiqs/
├── engine/          # 锁定：撮合、账本、评估器、交易日历、哈希校验
├── strategies/      # 可改：量化因子，每策略一文件，统一接口
├── playbook/        # 可改：LLM 层经验手册与提示词
├── agents/          # 盘前推荐、复盘、研究三个 Claude 入口
├── data/            # AKShare 拉取 + SQLite 缓存
├── notify/          # 企业微信推送
├── jobs/            # 每个时间点一个入口脚本，供任务计划调用
├── tests/
└── .env             # API key、webhook、月预算（不进 git）
```

## 数据源（AKShare）

| 竞价快照 | `stock_zh_a_spot_em` |
| 新闻 | 财联社电报、东财个股新闻 |

| 交易日历 | `tool_trade_date_hist_sina` |

已知局限：缺少完整退市股历史，回测存在幸存者偏差、结果偏乐观，报告中需标注。后续可换 Tushare Pro。

## 失败处理

| 故障 | 处理 |
|---|---|
| 数据源失败 | 重试 3 次 → 切备用源（东财/新浪互备）→ 仍失败则告警，当天不出推荐 |
| Claude 调用失败/超时 | 盘前：有盘前条件就按条件过滤，否则退回纯量化推荐，标注"未经 LLM 审核"；复盘：日报照发，摘要注明失败；研究：本次中止 |
| 中转失效（Claude Code 升级、账号被封） | 同上逐级降级，并推送告警；换官方 API Key 只需改 `.env` |
| 推送失败 | 重试 + 本地日志，下一条消息补报 |
| 电脑关机 | 开机按交易日历补跑结算、复盘；跳过过时推荐 |
| 锁定区哈希不符 | 立即停止研究循环并告警 |

## 测试

- 撮合规则固定用例：一字涨停买不进、T+1、各板块涨跌幅及各生效日期前后、费用计算、资金时序与卖出优先级、停牌与 NaN 数据。
- 防未来函数：策略接口只提供 t 日及以前数据，独立测试验证。
- 端到端：历史区间回放完整一日流程，推送走 mock。
